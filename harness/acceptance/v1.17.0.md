# v1.17 公开正文留存与自然协作验收

## 结论与范围

已实现公开正文先于留存的操作指引、错误来源的发现指引，以及纯协议标记空正文的拒绝。默认 v1 仍只留存宿主取回的原作者公开消息，没有自由正文字段、推理提取或代写接口。

本次自然协作样本走通了公开决定、主动 `board_store`、完整引用派发、两个接收者主动 `board_get` 的链路。另一只读样本先完成公开报告，再由宿主自动留存。它们是有限样本，不证明模型永不漏存、转述或重复查询。

## 用户截图与修复

截图中调用使用 `session_id=ses_main`、`message_id=msg_未定`，消息只表达“先落板、随后给完整解释”，尚无完整报告。拒绝是正确行为。修复保留拒绝，并增加查询真实消息 ID 的反馈；自己的会话省略会话参数，其他会话使用实际宿主身份。

回归用例核对：占位 ID 不得读取未知来源；隐藏 reasoning、工具参数、synthetic 文本不能补成正文；仅有发布意向时只能留存该意向，不能因标题为“评审”生成报告；只有保存标记而无正文的消息在发现、显式保存与自动保存中均拒绝。系统不判断已公开结论在语义上是否完整或正确。

## 自然多 agent 协作

输入要求修复 `retry.py`：在两个策略中按需求选取一个，由实施者修复、另一人独立检查。需求上限为三次、仅超时可重试、取消优先；三个测试和需求文件不可修改。任务不提示保存或阶段化输出。

实际轨迹：

1. 主角色公开策略 B 的选择、理由和限制。
2. 第一次 `list` 时同条决策消息尚未结束，列表未包含它；下一次查询取得真实消息 ID 后，仅调用一次 `store`，以 `decision` 保存原文。
3. fixer 收到完整决定 ID，在编辑前 `board_get` 读取原文，仅修改 `retry.py` 的重试条件。
4. 新 Oracle 会话收到决定和实现者原始记录，主动读取两条来源，核对代码版本、运行测试和边界检查。
5. 主角色最终答复保留决定、实现者及评审的完整记录链接。记录正文与宿主公开 text parts 逐字一致，来源快照哈希通过核验。

这个样本共三个会话、四条记录（一条阶段决定、三条最终答复），一次显式 `store`、两次 `board_get`，两条派发边均传递并实际读取原始引用，没有把整份作者记录复制进派发正文。外部复跑三个业务测试通过，需求、选项和测试文件与事前快照一致。

独立评审的原结论是“功能 PASS、历史范围证据 BLOCKED”：实现者报告没有附三个受保护文件的事前哈希。主角色随后自行核对其事前读取内容和现状，并复跑测试；没有第二次独立复审，不能把原评审改称无条件 PASS。外部验收持有真实事前文件快照，确认受保护输入未变。

## 只读报告样本

任务要求审阅公开正文来源边界，给出结论、依据和限制，没有保存指令。主角色自行审阅后输出完整公开报告，未显式调用保存工具，宿主自动留存一条原文记录。该样本没有派发子任务，不算第二个多 agent 样本。

报告中的“两个独立纯标记防线”表述不准确：纯标记空正文由 `publicReply` 拒绝，`captureFinal` 的普通 `trim` 检查不是同等规则。验收以实现和专门回归测试为准，不把模型自述当成独立证明。

## 保留的限制与证据

- 协作仍有一次额外消息查询，以及要求实现者回传完整短代码的冗余；没有宣称实现零转述或稳定提速。
- 普通进度正文仍可按明确请求留存；标题和类别不证明正文已包含报告内容。
- “用户可读”依据宿主公开消息分类，不是对所有客户端 UI 渲染的自动验证。摘要标题由请求者提供，原文作者不承担该标题的语义正确性。
- 只读来源缺少编辑日志时记录 `edit_evidence_unavailable`，不会用当前文件补造历史版本。版本快照正确不等于语义验收。
