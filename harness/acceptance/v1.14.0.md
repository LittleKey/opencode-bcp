## 系统修复

1. **留存授权**：接受顶层独占行的正向标记，不因其前面有说明文字而丢弃。代码、引用、缺失标记及禁止标记仍按契约拒绝；原文不改写。
2. **工件版本**：从同一准入输入的原生编辑观察绑定确切文件快照。旧输入的迟到回调不能归入新输入；重放不重新抓取变化后的文件。
3. **交接来源**：自动附带已知作者工件、当前输入的阶段决定，以及原作者修订所需的可读评审来源。旧记录重读不提升为新版本。只有逐字相同的工件副本可以机械替换，不能推断或改写语义。
4. **原生续接**：OMO 原先在子任务已经返回后才设置新代次的开始时间，导致本轮终结消息被当成历史消息。改用实际派发时间；已有证据读取未完成时等待其完成信号，再进入原终态闸门，最多两次、每次最多两秒。仍检查调用身份、代次与取消状态。
5. **终态确认**：原生续接仅可确认已注入给同一父会话、角色一致且代次与终态修订完全相同的结果；不确认未注入、过期或其他任务的结果。没有新增模型重试、自动补发或第二套运行状态库。
6. **汇总核验**：验收结果从冻结运行指纹、原始消息、记录与字节生成；不同候选版本不拼接为同一次通过。记录存在与评审意见均不自动等于语义验收。

## 最终主验收：六个场景

业务请求不提 BCP、保存、摘要或授权标记。原生续接探针显式限定 Task 的调用方式，用于验证协议，不用于证明模型会自发选择该方式。

| 场景 | 实际观察 |
|---|---|
| 简短计算 | 正确答复；一次自动留存、零工具调用。 |
| 明确禁止留存 | 零 BCP 记录、零工具调用。该结论不表示删除宿主聊天历史。 |
| 调查并修改代码 | 五项独立业务测试通过；原生编辑自动绑定实际版本，无手动发布。 |
| 文档写作与独立评审 | 一位 document-writer 与一位 Oracle；评审读取原作者记录；两者绑定同一实际文件版本；主角色引用实际评审记录，无整份工件复制。 |
| 阶段选择后并行落实 | 恰好一次主动 `decision`，完成后才派发；两个执行者均先读取同一原始决定，再写入各自产物。 |
| 原生 Task 续接 | 恰好两次成功调用、同一子会话；执行代次、输入消息、终结消息和作者记录正确更新，均返回 `completed` 与宿主消息身份。无额外模型错误重试。 |

主验收共 6 个根会话、11 个含子会话的会话、51 个 assistant 步骤，12 次自动留存、1 次阶段手动发布；报告的输出 token 合计 22,618。耗时包含模型、工具和观察器静默等待，不能解释为插件耗时，也不是提速或计费单位对照实验。
