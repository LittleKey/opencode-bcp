- 源码仓库基线提交：`79c7a84e073506a12f7d909fedbb05b4f4b0327e`。旧规则使用 `git show :src/constants.ts` 中修改前已暂存的用户版本，保留用户 v1.8.8 长内容建议；不是丢弃用户改动后的 HEAD 常量。
- Bun 构建时仅替换常量模块的输入；源码及 git 索引未切换。其余实现、角色提示、模型、配置一致。旧版构建 SHA-256：`78bd26d09579d280687f116d8b1bb22e50378cca204390e98c187b019f4845ed`。

- 每个版本启动独立临时宿主 OpenCode 1.18.31。父会话为配置中的 orchestrator（newapi/glm-5.3）；由它实际调用 OMO task，子会话使用配置中的 explorer/fixer（newapi/glm-5.3-flash）。没有替代为直接向子角色发消息。
- 父任务同义且采用相同模板；查询使用同一 fixture。修改任务只以 baseline/candidate 文件名前缀区分，初始内容均为 `before`。快照允许创建，禁止 git 提交、不要求新增测试。每个父会话仅允许一次前台委派，禁止重新派发、追加评审或自行代做。

- 宿主工具导出与 hook 观察中的 board_put、board_get 文案均与相应常量逐字相同；task 文案都包含相应版本的完整 TASK_DESC_APPEND。task 的其余描述在导出与 hook 形态间不同，因此只验证 BCP 契约片段相同，不宣称完整 task 文案完全相同。没有捕获发往模型服务商的最终 HTTP 请求。

## 观察结果

| 场景 | 旧规则 | 候选规则 |
| --- | --- | --- |
| 父任务实际派发 | 有 task 契约，但派发正文未提 board / bb 或持久交付 | 相同 |
| explorer 普通查询 | 读取后只返回答案，无作者记录；父会话自行写摘要 | 相同 |
| fixer 文件改动 | 读回验证；保存快照、发布 change，但缺快照 SHA | 读回验证、发布 change；未保存快照，仅引用可变路径，并将 Limits 写为“无” |
| 父会话接收改动 | board_get 后宣称“无缺失项” | board_get 后宣称“交付无缺失” |

查询的 marker 提取本身正确。父角色把“准确来源”解释为 fixture 内声称的外部出处；源文件实际只有标题、marker 和测试用途限制。这个解释偏差与持久交付问题分别记录，不用它证明来源校验成功。

父会话把“不得追加评审/重跑”作为未复核的原因，但原任务允许阅读既有来源并要求如实报告交付缺口。正式独立评审、重新派发与接收交付时的来源核对是不同操作。不能将其宣称为用户禁止了一切核对。
