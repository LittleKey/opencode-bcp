## 结论与职责边界

运行实现通过限定范围的技术验收：长结果可在严格来源绑定及接收者可读取条件下呈现为引用回执；Council 继续使用原有主角色派发机制，由宿主装配席位原文。两项独立首审发现的 Council 阻塞均已修复，第一次复审确认关闭。角色与维护配置完成加载和一致性检查。

这些结果不意味着模型永远正确选择角色、保留所有限制或形成正确结论。宽域自然任务曾超过观察时限，后经同一会话的受控续接完成；该例不能计为一次无干预完成。评审原判归属不被主角色的补充核验替代。

## 新进程观察

所有场景使用单独启动的 OpenCode 进程加载新配置，结束后关闭该进程。没有要求用户先重启当前 UI。

| 场景 | 实际观察 | 限制 |
| --- | --- | --- |
| tiny | 版本文本 1→2，主角色直接完成，无 Task | Bash 写入，不作为原生编辑快照测试 |
| reference | 10,990 字节作者原文完整保留，父角色 Task 返回合计 2,548 字节，含可读取引用和元数据 | 这是明确要求长探索输出的受控例；父角色另行检查原文件，没有用该例证明后续消费者必然读取引用 |
| planning | 未指名角色；主角色请求 Oracle 独立挑战，保留其 REJECT | 小样本未启用 explorer；不能据此声称广域调查已隔离 |
| planning-wide | 未指名角色；主动派发 explorer 与 Oracle，两个调查均完成 | 首次等待 720 秒超时，主角色汇总被观察器中断；随后同 root 续接，两个子会话逐字未变，无新调查 |
| council-final | 四席与综合席完成，四份宿主装配正文与真实消息逐字相同；综合席无工具调用 | 条件性设计判断，不是代码正确性证明；一个席位仍执行了用户未要求的只读操作，不能声称完整指令服从 |

宽域样本只复制 `src/` 与 `test/`，不含 `integrations/omo-slim/`。其中关于 generation 的判断必须限于这份不完整快照，不能推翻生产 OMO 的代次核验。最终报告虽注明该边界，正文的部分概括仍过宽。探索原答因发布限制没有入板，原始 Task 答复保留；不能把该场景算作完整的引用式交付成功。

Council 原文通道解决的是归属、版本与逐字传递。主角色仍可能简短复述观点；综合席的“共识”表述也不能替代逐席语义核验。配置不能提供模型永不误判的保证。
