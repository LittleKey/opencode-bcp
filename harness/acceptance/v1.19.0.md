## 读者对照方法

六个问题在作者运行前封存：策略和次数语义、HTTP500 与取消优先级、实际修改与检查、独立评审最终结论、受保护文件历史证据，以及不存在依据的“生产错误率下降 30%”。来源组标注在读者运行前固定；标注由本次执行者制定，不是独立盲评。

四个全新读者使用相同原文、问题、权限和模型。测试限制读者只使用板来源，并禁止新增记录，避免前一读者的总结污染后一组。三条原记录及其工件哈希在测试前后相同。

- **旧标题目录**：测试插件仅把目录返回的 description 替换成旧首行算法的结果，`board_get` 原文不变；使用同一个跨流目录接口，不模拟旧版默认本人流的限制。
- **作者标题目录**：相同目录接口，使用实际保存的新标题。
- **正文搜索**：受控要求使用 query 发现，再读取原文。
- **自主选择**：不提示目录、搜索或工具名称，自行选择发现路径。

前三组明确规定发现方式，属于受控对照；第四组验证自主选择。作者与读者均使用独立启动的宿主进程，不依赖用户重启正在使用的会话。

**配置版本边界**：封存检查拒绝了“作者与读者共用同一配置”的假设。两阶段之间，orchestrator、designer、fixer 新增 `apply_patch: allow`，librarian、explorer、observer 新增 `apply_patch: deny`；模型、角色提示和插件产物未变。原配置从此前归档按作者运行时哈希恢复核验，新旧配置的 JSON 差异仅为这六项权限。两个阶段各自运行前后指纹一致，四个读者组都使用同一份新配置；不存在对照组之间切换配置。两份配置分别封存，不修改现有配置，也不把作者阶段声明为新权限配置下的自然行为验证。

四组 get 返回均为 14749 字节。一次 get 包含三个 ID，不能解释为只读了一份记录。工具字节是实际返回文本的 UTF-8 长度，不是模型 token 或计费单位；耗时包含宿主等待与模型服务，单次顺序运行和缓存差异不足以证明因果提速。

机器核验了完整目录、原文与 canonical record 一致、记录文件 SHA-256、先发现后读取、引用来自已读记录、无其他工具和无新记录。人工回读四份答复：六个问题的核心答案均与原文相符，都保留独立评审的 BLOCKED、区分协调者自述与独立历史证明，并拒绝无依据的 30% 声称。部分答复用“无编辑日志”概括受保护文件证据缺口，措辞不够精确；实现者实际存在 retry.py 的原生编辑证据，不能扩成所有作者均无日志。

## 边界与后续取舍

本轮只包含一个小 scope、三份同主题来源和六个问题，各目录组都选择读取全部记录，未覆盖噪声记录较多、跨主题目录或强制有限 get 预算。因此可确认目录入口可用、标题更有辨识信息、自然读者能主动采用该入口；没有证明新标题比旧标题提高召回，或模型能仅看标题可靠判断结论。

正文搜索保留为细节和较大目录的补充。目录完整只说明授权范围内的扫描和分页，不表示任意问题已有充分证据；标题不会自动推断版本关系或替代原文验收。不会为修正一个标题追加模型续轮、修改原始记录或扩大访问权限。
