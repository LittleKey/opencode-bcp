# BCP v1.12 宿主交付集成

本契约细化已批准的交付职责设计。BCP 提供证据与关联事实；OMO 保持执行权威；接收者承担语义验收。

## 身份与重建

OMO 2.2.25 原终态门从宿主 transcript 核验执行结束。在原有代次、提交保护内，额外保留最终 assistant 消息 ID 及其 parentID 指向的输入 ID，与原结果进入同一 job 对象；新运行及重回运行状态时清除旧字段。不根据作者文字、同名角色或时间接近推断身份。

v1 BCP 接收按项目目录分开的进程内 `Symbol.for("opencode.bcp.delivery.v1")` 调用，不增加模型工具。调用者须已注册；宿主须证明被查询子会话属于调用者。BCP 重核输入与终结消息的会话、角色和父子关系，能力或身份不足返回 `unconfirmed`。

持久记录的 writer 与宿主消息用于重建来源，不建立第二套交付数据库。同一作者会话的记录按消息父关系分为 `current_input`、`prior_input`；其他作者为 `other_author`；缺少消息为 `unconfirmed`。标签不证明覆盖。重启后若 OMO 代次不可恢复，允许保留宿主消息级关联，但代次为空；消息也缺失则不确认。

## 逐项事实

只从宿主核验的作者最终答复提取最多 8 个候选 board ID，不扫描黑板。出现 ID 不等于终结报告或合法复用；零候选不自动判定漏交付。

每项先按接收者权限检查。隐藏流与未找到同形，不泄漏其来源或作者。可读项返回原 writer、记录 hash、归属、可见导航边以及最多 16 项来源检查，并显式标记截断。保留快照校验字节；普通 URL、相对路径不自动验证；其他 board 引用只查可读性，不递归遍历。元数据不返回记录正文。

`coverage`、`applicability` 固定为 `not_evaluated`，没有综合 accepted=true。接收者仍按现行规则读原文，或复用准确版本仍在上下文中的已有核对。

## 返回与生命周期

前台 task、task_result、后台通知、task_revive 使用同一检查函数。保留原文，在其外附 `<bcp_delivery_metadata>` JSON 块；前台另附工具 metadata。此为 DESIGN §11.8 “不自动改写子任务返回结果”的窄化例外：仅允许独立检查元数据，不允许改写、冒充作者或强制重复发布。

首次后台完成的宿主原生通知在进入模型上下文的 transform 阶段附加元数据，不修改已保存的通知原文。后续 transform 仅对原宿主确认仍属当前代次的通知重新检查，同一结果不重复附加；旧代次与删除前事件不转属新运行。因此验证这条路径须检查模型上下文，不能仅查消息存储。恢复任务的 OMO 通知在原有发送路径附加，并继续受通知租约保护。

检查后继续使用原有代次、修订及通知租约保护。运行中、异常终结或准入未确认时不虚构关联。检查失败不补写、不调用模型、不新增唤醒。单次宿主等待最多 2 秒，返回 JSON 最多 65,536 个字符，超界保留未知；超时不承诺中止已经发出的宿主只读请求。

当前仅接入 OpenCode v1 与固定 OMO 2.2.25 的本地适配；v2 构建兼容不等于 v2 运行集成已经验收。独立 BCP 不附带 OMO 的生命周期能力。

## 保留边界

默认直接、委派、只读、受阻任务的交付义务保持。只读漏发、外部写入、发布限制、评审与实际输入版本错位仍需作者与接收者处理。没有自动验收、强制依赖门禁、最终回答阻断或修复循环。

具体源码版本与实测范围见 `harness/acceptance/v1.12.0.md`；设计文字本身不证明模型遵约率或端到端可靠性。
