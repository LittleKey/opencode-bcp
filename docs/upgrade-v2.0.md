# 2.0.0 双宿主升级

本版本提供按宿主安装的 OpenCode v1/v2 兼容方案。2.0.0 已通过发布复审并安装到现有 v1 生产配置，新进程配置检查与一次服务端 API 实际模型冒烟通过。生产 CLI 保持 1.18.33，未迁移数据库。具体范围与限制见 [`harness/acceptance/v2.0.0.md`](../harness/acceptance/v2.0.0.md)。

## 版本组合

| 组件 | 版本与边界 |
| --- | --- |
| OpenCode v1 | 声明最低 1.18.29，实际验证 1.18.33 |
| OpenCode v2 | 声明最低并实际验证 2.0.20 |
| opencode-bcp | 2.0.0，同一个构建产物提供 `server` 和 `setup`；宿主协议分别适配 |
| OMO Slim | 3.0.1，上游 Council 不变，保留锁定源码的 BCP 协作补丁 |
| billion-context | 0.1.175，使用上游原生入口及文件恢复语义，完整依赖作为固定安装包保存 |
| document-writer | 2.0.0，安装时选择宿主格式，正式文档与平台操作角色保持分工 |

最低版本声明不代表所有中间版本和未来版本都已验证。补丁构建校验上游源码摘要及唯一锚点；新的上游版本需要重新检查，不能直接套用。

## 协作职责

BCP 保存原作者公开正文、真实消息身份、权限、输入版本及可观察的文件版本证据。OMO 保持执行代次、终态、取消、恢复和通知租约的权威。接收者读取原文后判断结论、覆盖范围与限制。正文留存或哈希一致不代表语义验收通过。

主角色不再组织私人 Council 席位流程。Council 使用上游自身实现。跨角色协作优先传递可读取的原始来源引用；大段正文只有在作者、当前输入、终态、原文摘要和接收者权限均得到验证后，才呈现为更短的引用回执。不确定时保留原文。

压缩采用 billion-context 的原生方案。旧 ACP 的 `minContextLimit`、`summaryBuffer` 等设置没有全部一一对应，不声称旧配置或内联恢复语义完全等价。旧配置与数据保留用于回滚。

## BCP 安装

先构建，再使用真实宿主可执行文件进行安装期检测：

```bash
bash scripts/build.sh
bash scripts/install.sh --host /absolute/path/to/opencode --artifact dist/blackboard.ts
```

项目安装要求目标目录已经存在：

```bash
bash scripts/install.sh --project /absolute/path/to/project --host /absolute/path/to/opencode --artifact dist/blackboard.ts
```

同一有效配置栈只能有一个 BCP 入口。独立安装器管理 `<config-root>/plugin/blackboard.ts`，其他全局、祖先或项目范围的冲突会在写入前报告。不能保留旧入口又另加 `plugins/blackboard.ts`。完整个人组合使用自己的管理清单；从独立入口迁移时必须明确备份、交接旧入口，后续按该组合的升级流程维护，不能混用两套文件所有权。未受管理的旧文件只有在显式指定其真实摘要后才能采用；文件名和注释不是所有权证据。

安装器保存原文件并对可捕获的失败执行回滚，不改写黑板数据。它不提供断电或 SIGKILL 下的跨文件事务保证。

## 完整个人组合

个人组合由 dotfiles 的 `opencode/runtime/` 安装流程管理，公共 BCP 包不内置个人模型、认证信息或项目技能。正式安装必须保留现有认证、模型、权限、完整角色正文与技能引用。测试环境的认证清理不能直接作为生产配置使用。

安装前冻结所有入口、依赖、资源和交付 helper 的摘要。搬迁验证必须脱离原暂存目录；只校验入口摘要不能证明运行包完整。已有提示目录的符号链接和无关用户文件不能强行替换。

固定的 billion-context 包必须关闭原地自动更新，避免目录名仍标为旧版本而内容已经改变。更新需要生成新冻结包并重新验收。

v2 隐私的实际支持范围为 HTTP/SSE：消息类正文脱敏、用户存储原文保留、跨分片恢复、已解析工具参数还原及会话隔离。没有稳定连接身份的匿名并发 WebSocket 场景不在完整保护保证内。当前 HTTP provider 的升级不能被描述为全部传输协议均已验收。

## 验收与生效

已完成的双宿主协议验证覆盖作者、独立评审、拒绝后原作者返修、原评审复审、原文读取和最终结论绑定。这些测试使用实际宿主及脚本响应，真实模型请求为零；不证明自然模型的判断质量或所有文件编辑历史。

隐私传输、完整个人组合的安装回滚和最终发布评审是独立验收条件。不得用角色目录可见或插件成功加载替代这些检查。

配置在新 OpenCode 进程启动时加载。安装后需要新进程核对实际插件和角色；当前长会话不会热更新。生产切换应保留可恢复的旧配置及安装包，不通过终止无关忙碌会话来完成验证。

本次已备份旧入口并安装固定组合，认证来源字节保留。服务端 API 以 `orchestrator` 实际调用 `newapi/glm-5.3` 返回预期正文；独立 CLI `run` 的两次探针未在期限内完成，未证明请求到达模型服务，不列为通过。原 UI 进程保留其旧配置；退出并重启 OpenCode 后才在该进程生效。
