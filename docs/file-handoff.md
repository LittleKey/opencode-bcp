# File handoff guidance

These repository examples are not installed configuration. Use only after archive
capability and reader/retention admission are proven, in an explicitly selected
configuration/session. Preserve existing append rules.

## Orchestrator append (two sentences)

Use the task's supplied .opencode/work/<task-id>/ root for working reports and scratch outputs, and the agreed project document paths for formal deliverables.
When earlier material matters, including review verdicts and corrections, pass its exact-version file paths with the new task or delta instead of retelling it; reuse existing files, save only when needed and authorized, and disclose missing evidence.

## Dispatch and access boundaries

The actual cwd, task root, allowed Read/Write paths, scope and acceptance criteria
travel in normal dispatch, not dynamic system prompts. Paths do not authorize
retention or grant write access. No skill is required for ordinary use. Keep
existing router/progress/topic paths unchanged; do not double-write progress.
Missing or incomplete captures are evidence gaps, not successful copies.

Provide accessible project-relative evidence paths to exact-version files, with
their source and task. Resolve paths from the reader's project cwd; a different
worktree does not automatically share files. Ask the reader to read the referenced
text files, or the manifest and relevant parts for multipart results, cite files
used and disclose unavailable or incomplete evidence.

No wrapper/guard permission changes or automatic aliases/copies/exports are
authorized by these examples. Report inaccessible evidence as a gap; do not
expand permissions or automatically copy/export files to repair a read failure.
